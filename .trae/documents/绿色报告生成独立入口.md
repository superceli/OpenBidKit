# 绿色报告生成独立入口

## Context

现有"绿色报告"功能嵌在"标书生成"二级菜单下，仅支持报告类型选择→目录→正文三步，缺少企业知识库检索、页数/样式配置和 PDF 导出。用户要求新建一个独立侧边栏入口"绿色报告生成"，支持输入企业→检索知识库→选择报告类型与配置→智能生成→导出 PDF/Word。

用户确认：移除原有子项统一到新入口；知识库按公司名搜索作为生成上下文；PDF 用 LibreOffice 转换。

复用现有 SectionId `green-report`（已贯穿 navigation/router/IPC/traffic），只需从 bid-generation 子项提升为顶级菜单项，避免大规模改名。

## 实现步骤

### 1. 类型与状态 — `src/features/green-report/types.ts`

- `GreenReportStep` 改为 `'company-info' | 'report-config' | 'outline' | 'content'`
- 新增 `GreenDocumentStyle = 'standard' | 'narrative' | 'data-driven' | 'academic'` 及 `GREEN_DOCUMENT_STYLE_LABELS`
- 新增 `GreenKnowledgeContextItem { documentId, documentName, itemId, title, resume, content }` 和 `GreenKnowledgeContext { keyword, items, searchedAt }`
- `GreenReportState` 新增 `pageCount: number`、`documentStyle: GreenDocumentStyle`、`knowledgeContext: GreenKnowledgeContext | null`
- `GREEN_STEPS` 改为 4 步；`GREEN_STEP_LABELS` 对应更新；`DEFAULT_GREEN_PROJECT_INFO` 旁加 `DEFAULT_GREEN_REPORT_CONFIG = { targetWords: 20000, pageCount: 30, documentStyle: 'standard' }`

### 2. 菜单与导航

**`src/app/menuConfig.ts`**：从 `bid-generation.children` 删除 `green-report` 子项；在 `appMenuItems` 中 `bid-generation` 之后新增顶级项 `{ id: 'green-report', label: '绿色报告生成', description: 'ESG、可持续发展、社会责任等绿色报告生成', badge: 'Beta' }`。`navigation.ts`、`AppRouter.tsx` 无需改动。

**`src/components/Sidebar.tsx`**：新增 `LeafIcon` SVG 组件（绿色叶子造型），`navigationIcons['green-report']` 从 `DocumentIcon` 改为 `LeafIcon`。

**`analytics/dashboard/public/src/pages/traffic.js`**：更新 `green-report` 标签为 `绿色报告生成`，新增 `green-report/company-info`、`green-report/report-config` 子路由中文名，保留旧 `green-report/report-type` 兼容历史会话。

### 3. UI 页面重构 — `src/features/green-report/pages/`

- **新建 `CompanyInfoPage.tsx`**（step 0）：企业名输入 + 行业/报告期/范围/议题 + "搜索知识库"按钮调用 `window.yibiao.knowledgeBase.searchItems(companyName)`，展示匹配条目列表（标题+摘要），勾选纳入生成上下文。Props: `state, draftProjectInfo, onDraftChange, onSaveProjectInfo, onSaveKnowledgeContext`。

- **新建 `ReportConfigPage.tsx`**（step 1）：6 种报告类型选择网格 + 生成页数(number, 5–200, 默认30) + 文档样式(select) + 目标字数(number)。Props: `state, onReportTypeChange, onSaveReportConfig`。

- **删除 `ReportTypePage.tsx`**：职责拆分到上述两个新页面。

- **`OutlinePage.tsx`**：移除 `targetWords` 输入框（移至 ReportConfigPage），`onOutlineChange` prop 简化。

- **`ContentPage.tsx`**：头部新增"导出 Word"和"导出 PDF"按钮。Props 新增 `onExportWord, onExportPdf`。

- **`GreenReportHome.tsx`**：`emptyState` 加 `pageCount/documentStyle/knowledgeContext`；4 步指示器自动适配；step 0 渲染 CompanyInfoPage、step 1 渲染 ReportConfigPage；新增 `handleSaveKnowledgeContext`→`greenReport.saveKnowledgeContext`、`handleSaveReportConfig`→`greenReport.saveReportConfig`、`handleExportWord`→`export.exportWord(payload)` 订阅 `onWordExportProgress`、`handleExportPdf`→`export.exportPdf(payload)` 订阅 `onPdfExportProgress`。`startGreenReportOutline/Content` payload 加入 `pageCount, documentStyle, knowledgeContext`。`trackPageView` 改为 `green-report/${state.step}` 埋点子路由。

### 4. 后端 Store — `electron/services/greenReportStore.cjs`

- `loadMeta`：读取 `page_count`、`document_style`、`knowledge_context_json`
- `loadState`：返回新字段及默认值
- `saveMeta` INSERT 分支补 `page_count, document_style, knowledge_context_json` 列
- 新增 `saveReportConfig({ targetWords, pageCount, documentStyle })` 和 `saveKnowledgeContext(context)`
- `updateGreenReportWithoutReload` 加 `pageCount/documentStyle/knowledgeContext` 字段处理
- return 对象加 `saveReportConfig, saveKnowledgeContext`

### 5. SQLite 迁移 — `electron/services/sqliteDatabase.cjs`

- `schemaVersion` 从 `23` 改为 `24`
- `createGreenReportSchema(db)`：`green_report_meta` CREATE TABLE 加 `page_count INTEGER NOT NULL DEFAULT 30`、`document_style TEXT NOT NULL DEFAULT 'standard'`、`knowledge_context_json TEXT`；DEFAULT step 从 `'report-type'` 改为 `'company-info'`
- `migrations` 数组末尾加 `{ version: 24, description: '新增绿色报告配置字段', up: createGreenReportSchema }`
- `schemaHealthColumnGroups` 加 v24 条目 `{ version: 24, table: 'green_report_meta', columns: { page_count: ..., document_style: ..., knowledge_context_json: ... } }`（让已有库 ALTER TABLE 补列）
- **`sql/workspace_schema.sql`**：同步 `green_report_meta` 表结构

### 6. 知识库搜索

**`electron/services/knowledgeBaseStore.cjs`**：新增 `searchItemsByKeyword(keyword, options={})` 方法 — 跨 `knowledge_items` JOIN `knowledge_documents`，`WHERE kd.status='success' AND (ki.title LIKE ? OR ki.resume LIKE ? OR ki.content LIKE ?)`，标题命中优先排序，LIMIT 20，content 截取 800 字。return `{ keyword, items }`。加入 return 对象。

**`electron/services/knowledgeBaseService.cjs`**：return 对象加 `searchItems(keyword, options) { return knowledgeBaseStore.searchItemsByKeyword(keyword, options); }`

**`electron/ipc/knowledgeBaseIpc.cjs`**：加 `ipcMain.handle('knowledge-base:search-items', (_e, kw, opts) => knowledgeBaseService.searchItems(kw, opts))`

**`electron/ipc/index.cjs`**：`workspaceDatabaseChannels` 加 `'knowledge-base:search-items'`

### 7. Prompt 增强 — `electron/services/greenReportPrompts.cjs`

- 新增 `DOCUMENT_STYLE_GUIDANCE` 常量映射（standard/narrative/data-driven/academic 各自写作指引）
- `buildOutlineSystemPrompt(reportType, documentStyle='standard')`：末尾加风格指引
- `buildOutlineUserInstruction(reportType, projectInfo, { pageCount, documentStyle, knowledgeContext })`：加 `生成页数：${pageCount} 页`；若 `knowledgeContext?.items?.length`，追加知识库资料区块
- `buildContentSystemPrompt(reportType, documentStyle='standard')`：加风格要求
- `buildContentUserInstruction(node, projectInfo, reportType, { documentStyle, knowledgeContext, pageCount })`：注入相关 KB 条目作为章节参考

### 8. 任务层 — `electron/services/greenReportTasks.cjs`

- `runGreenReportOutlineTask`：从 payload 解构 `pageCount, documentStyle, knowledgeContext`，传入 prompt builder
- `runGreenReportContentTask`：同理，从 payload 取新字段传入 content prompt builder

**`electron/services/taskService.cjs`**：green-report 任务定义的 `step` 元数据从 2/3 改为 3/4（纯元数据，无逻辑依赖）

### 9. PDF 导出

**新建 `electron/utils/libreOffice.cjs`**（CJS）：从 `doc2markdown/convert.mjs`（ESM，无法直接 require）提取并适配：
- `findLibreOfficeCommand()`：候选列表 = `[LIBREOFFICE_PATH, 'soffice', 'libreoffice', macOS 路径, Windows 默认安装路径]`，绝对路径 `existsSync` 检查，相对命令 `spawn --version` 探测
- `runLibreOfficeConvertToPdf(soffice, inputPath, outputDir)`：`spawn` soffice `--headless --convert-to pdf --outdir outputDir inputPath`，临时 profile 目录，180s 超时，`windowsHide: true`

**`electron/services/exportService.cjs`**：return 对象加 `async exportPdf(payload={}, onProgress)`：
1. `findLibreOfficeCommand()` → 无则 return `{ success: false, libreOfficeMissing: true, message: '未检测到 LibreOffice...' }`
2. `dialog.showSaveDialog` 选 .pdf 路径
3. `mkdtemp` 建临时目录，`buildDocxResult(payload)` 生成 docx buffer 写临时 .docx
4. `runLibreOfficeConvertToPdf` 转换，`copyFileSync` 到目标路径
5. finally 清理临时目录；进度通过 `onProgress` 回调

**`electron/ipc/exportIpc.cjs`**：加 `ipcMain.handle('export:pdf', ...)`，结构同 `export:word`，发 `export:pdf-progress` 事件，不触发捐赠弹窗

### 10. Preload 与 IPC 类型

**`electron/preload.cjs`**：
- `greenReport` 加 `saveReportConfig(payload)` 和 `saveKnowledgeContext(context)`
- `knowledgeBase` 加 `searchItems(keyword, options)`
- `export` 加 `exportPdf(payload)` 和 `onPdfExportProgress(callback)`

**`electron/ipc/greenReportIpc.cjs`**：加 `green-report:save-report-config` 和 `green-report:save-knowledge-context` handler

**`electron/ipc/index.cjs`**：`workspaceDatabaseChannels` 加 `green-report:save-report-config`、`green-report:save-knowledge-context`

**`src/shared/types/ipc.ts`**：
- `greenReport` bridge 加 `saveReportConfig`、`saveKnowledgeContext`
- `knowledgeBase` bridge 加 `searchItems`
- `export` bridge 加 `exportPdf`、`onPdfExportProgress`
- import 新类型 `GreenDocumentStyle, GreenKnowledgeContext, GreenKnowledgeContextItem` from green-report types

## 验证

1. `cd client; node --check electron/services/greenReportStore.cjs`（及所有改动 .cjs）
2. `cd client; npm run build`（tsc --noEmit && vite build，既有 chunk 体积警告可接受）
3. `cd client; npm run smoke:electron-native`（SQLite 迁移变更）
4. `cd client; npm run dev` 手动验证：
   - 侧边栏出现"绿色报告生成"顶级入口，"标书生成"下不再有绿色报告子项
   - 4步流程：企业信息（搜索知识库）→报告配置（类型/页数/样式/字数）→目录生成→正文生成
   - 知识库搜索返回匹配条目
   - Word 导出正常；PDF 导出（装了 LibreOffice 时生成 PDF，未装时提示并降级）
   - 重启后状态恢复正常
